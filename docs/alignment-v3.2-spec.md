## 一、文档版本变更摘要（v3.1 → v3.2 关键增量）

### 1.2 开发规范 v1.0 核心强制约束（与现有代码冲突点）

| 规范要求 | 现有代码现状 | 冲突等级 |
|----------|-------------|----------|
| 金额 BIGINT 分（`xxx_amount_cent`） | 全部用 DECIMAL(10,2) | 🔴 必须改 |
| 必须有 OrderStateService | 不存在，状态散落在 OrderService | 🔴 必须新建 |
| 必须有 OwnershipService | 不存在，无归属快照逻辑 | 🔴 必须新建 |
| 必须有 BalanceAccountService | 不存在 | 🔴 必须新建 |
| 必须有 FabricSupplierService | 不存在 | 🟡 必须新建 |
| 库存操作幂等键 | 无幂等键机制 | 🔴 必须补充 |
| 库存 Outbox 事件模式 | 无 | 🟡 需设计 |
| Redis 锁需原子操作（SETNX） | 用 get/set 非原子 | 🔴 必须改 |
| 供应商映射需生效/失效时间 | 表有基础字段但无 Service | 🟡 需补充 |
| 价格版本化管理 + 锁定 30 天 | 有基础版本但无锁定机制 | 🟡 需补充 |
| 每副窗帘独立生产/质检/发货状态 | 只有主订单状态 | 🔴 需改造 |
| 状态变更历史表 | 不存在 | 🔴 必须新建 |
| 统一 API 响应含 request_id | 无 request_id | 🟡 需补充 |
| 幂等键接口清单（13 类接口） | 无 | 🔴 需补充 |

## 五、关键约束（全员必读）

1. **不动现有线上逻辑**：所有改造通过 Migration + 新 Service 实现，不直接改已有业务逻辑
2. **金额全部用分**：BIGINT 存储，bcmath 计算，前端展示时 ÷100
3. **状态机唯一入口**：OrderStateService 是唯一的订单状态变更通道
4. **快照不可变**：订单归属快照、供应商快照、价格快照一旦写入不可修改
5. **幂等必须**：所有涉及资金/库存/支付的接口必须有幂等键
6. **MySQL 是权威**：Redis 只做缓存和辅助锁，最终一致性以 MySQL 为准
7. **测试资金隔离**：测试余额绝对不能进入生产环境
