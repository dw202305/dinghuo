## 一、测试概述

### 1.1 测试目标
- 验证所有 API 接口功能正确性，覆盖门店端 + 后台管理端共 100+ 接口
- 验证业务规则（订单状态机、金额计算、库存并发、价格锁定、支付互斥、余额事务）正确性
- 验证数据一致性和完整性（含余额流水不可变、归属快照不受后续修改影响）
- 验证认证/权限/越权场景（含数据权限隔离：门店A不能看门店B的余额/订单/库存）
- 验证边界条件和异常处理
- 验证资金安全：余额并发扣减不出负数、充值回调幂等、事务回滚正确

### 1.3 测试策略

#### 测试类型
1. **接口功能测试**：验证每个 API 的正常和异常场景
2. **业务规则测试**：订单状态机、金额计算公式、价格锁定、支付互斥
3. **权限测试**：认证、角色权限、跨门店越权、数据权限隔离
4. **边界值测试**：尺寸范围、金额精度、分页参数
5. **并发测试**：库存扣减、余额支付、支付创建、订单提交
6. **数据一致性测试**：金额汇总、状态同步、日志记录、余额流水
7. **事务测试（v1.2 新增）**：余额扣减+订单更新的事务原子性、回滚验证
8. **幂等测试（v1.2 新增）**：充值回调重复、支付重复创建、余额支付重复提交

#### 测试优先级定义
- **P0**：核心功能，阻塞性缺陷，必须全部通过（含资金安全相关）
- **P1**：重要功能，影响主要业务流程
- **P2**：一般功能，可延后修复

```
横轨费用 = (180/100) × 120 = 216.00
竖轨费用 = (300/100) × 2 × 30 = 180.00
轨道费用 = 216.00 + 180.00 = 396.00
面料费用 = (180/100) × (300/100) × 单价
选装费用 = 电源加价 + 遥控器加价 + 墙控单价×数量
单副合计 = 轨道 + 面料 + 选装 + 套件 + 非标
```
